# Visual Style Guide v1.0

## 1. Мета

Усі зображення застосунку мають виглядати як частини одного продукту.
Візуальна система повинна бути зрозумілою, спокійною, не спортивно-агресивною і придатною
для користувачів різного віку, включно зі старшими людьми.

## 2. Загальний характер

- доброзичливий;
- нейтральний;
- чистий;
- простий;
- без «фітнес-моделі» або bodybuilding aesthetics;
- без акценту на схуднення чи зміну форми тіла;
- пози мають бути легко читабельними навіть на невеликому екрані.

## 3. Персонаж вправ

Canonical profile: `adult_neutral_01`.

Вимоги:
- доросла людина нейтральної зовнішності;
- звичайна, не надмірно атлетична статура;
- простий однотонний одяг;
- без великих логотипів;
- без медичного халата;
- без спортивного інвентарю, якщо він не потрібен вправі;
- у межах однієї вправи — одна й та сама людина, одяг, зачіска і пропорції.

Стать/вік персонажа не мають створювати враження, що вправа призначена лише для однієї групи.

## 4. Камера і композиція

Для кожної вправи YAML визначає:
- `view`;
- `camera`;
- `crop`;
- required body parts;
- environment.

У межах однієї вправи камера не змінюється.

Ключові частини руху не повинні виходити за crop.

## 5. Фон

Default:
- світлий або нейтральний;
- без декоративного clutter;
- без предметів, які не потрібні для вправи;
- достатній контраст із тілом/одягом.

Для лежачих вправ поверхня має бути видима, якщо контакт із нею є частиною техніки.

## 6. Стілець / ліжко / поверхня

Якщо вправа використовує опору:
- предмет однаковий у всіх кадрах;
- його положення не змінюється між кадрами;
- геометрія не «пливе»;
- стілець без коліс, якщо YAML вимагає stable chair;
- поверхня лежачи однакова в усіх кадрах.

## 7. Зображення не містить UI

У production asset заборонено вбудовувати:
- назви вправ;
- кнопки;
- цифри;
- стрілки;
- таймер;
- підказки;
- watermark;
- source logo.

Усе це рендерить Flutter UI.

## 8. Exercise frames

Одна вправа зазвичай має 2–6 окремих кадрів:
- start;
- one or more movement/intermediate frames;
- end/checkpoint;
- mirrored side frames за потреби.

Preview може бути окремим crop або одним із ключових кадрів.

## 9. Рух

Кадри мають чітко показувати механіку:
- що рухається;
- що залишається нерухомим;
- де є опора;
- де є контакт із поверхнею;
- які суглоби/кінцівки змінюють положення.

Не підсилювати амплітуду для «красивішого» кадру.

## 10. Симетрія

Для left/right варіантів:
- поза має бути дзеркально логічною;
- не змінювати камеру;
- не міняти положення меблів;
- не міняти одяг або пропорції.

## 11. Reduced Motion

Якщо користувач вимикає рух:
- застосунок показує статичні ключові пози;
- інформація не повинна залежати від плавної анімації.

## 12. Body Map

Body map має інший профіль: `body_map_v1`.

Вимоги:
- front + back;
- спрощена анатомічна форма;
- не фотореалістична;
- не спортивно-анатомічний плакат;
- достатньо нейтральна для широкої аудиторії;
- активні області не малюються всередині asset як постійний UI;
- Flutter накладає hotspots окремим інтерактивним шаром.

## 13. Основний принцип

**Asset показує тіло/позу. UI показує інформацію та взаємодію.**
